Төслийн зорилго ба бүтэц

Corg.ly нь нэг асуулт, 2–6 сонголттой санал асуулга үүсгэх, санал бүртгэх, үр дүнг харах сургалтын вэб апп юм. Үр дүнг серверийн Incoming Webhook холболтоор Slack суваг руу илгээх үйлдэлтэй. Энэ нэрийг лабораторийн жишээ төсөлд ашигласан бөгөөд өмнө нь байсан бүтээгдэхүүний албан ёсны баримтжуулалт биш.

Хэрэглэгч нь жижиг багийн санал нэгтгэх хүн болон туршилтын оролцогч байна. Сервер нь Python стандарт сан, SQLite ашиглана. Нэмэлт Python package, Node.js эсвэл өгөгдлийн сангийн тусдаа сервер суулгахгүй.

Хэрэглээний хүрээ

Апп зөвхөн 127.0.0.1 хаягт ажиллана. Нэвтрэлт, оролцогчийн таних тэмдэг, нэг хүн нэг санал гэсэн хязгаарлалт байхгүй. Иймээс ангийн эсвэл багийн бодит нууц санал хураалтад шууд ашиглахгүй. Нийтлэгдсэн сайт нь баримтжуулалт; санал асуулгын серверийг татаж авч локал ажиллуулна.

Анхны санал асуулгаа үүсгэх Tutorial

Зорилго: санал асуулга үүсгэж, нэг санал өгсний дараа нийт санал 1 болсон үр дүнд хүрэх. Энэ Tutorial нь анх удаа ашиглаж буй хүнд зориулсан 8 алхамтай. Алхамын тоог лабораторийн зааврын Bhatti бүлэг 2, хуудас 31–32 гэсэн шаардлагад тохируулсан [1, 2].

Урьдчилсан нөхцөл

Python 3.10 эсвэл түүнээс шинэ хувилбар, терминал, веб хөтөч, задалсан corgly-project хавтас шаардлагатай. 8000 порт сул байна. Slack бүртгэл энэ Tutorial-д хэрэггүй. macOS болон Linux дээр доорх командыг ашиглана.

1 Python хувилбарыг шалгах

Терминал нээж хувилбараа шалгана. 3.10 буюу түүнээс шинэ байх ёстой.

python3 --version

2 Төслийн хавтас руу орох

ZIP-ээ задалсан байрлалаас ажиллуулна. Хавтсын нэр corgly-project байна.

cd corgly-project

3 Серверээ эхлүүлэх

Терминалыг нээлттэй үлдээнэ. Corg.ly хаяг хэвлэгдэнэ.

python3 server.py

4 Аппыг нээх

Хөтөч дээр http://127.0.0.1:8000 хаягийг нээнэ. Шинэ санал асуулга маягт харагдана.

5 Асуултаа бөглөх

Асуулт талбарт “Дараагийн уулзалтыг хэзээ хийх вэ?” гэж бичнэ. Сонголтууд талбарт “Даваа”, “Мягмар” гэдгийг тус тусдаа мөрд бичнэ.

6 Санал асуулга үүсгэх

“Үүсгэх” товч дарна. Асуултын карт, хоёр сонголт, нийт санал 0 гарна. Карт дээрх ID-г тэмдэглэнэ.

7 Нэг санал өгөх

“Даваа” гэсэн сонголтын товчийг нэг удаа дарна. Нийт санал 1, Даваа сонголтын санал 1 болно.

8 Үр дүн хадгалагдсаныг батлах

Хуудсыг шинэчилнэ. Нийт санал 1 хэвээр байна. Ингэснээр санал асуулга болон санал SQLite файлд хадгалагдсан нь харагдана. Дуусмагц терминалд Ctrl+C дарж серверийг зогсооно.

Гарах үр дүн: нэг санал асуулга, хоёр сонголт, нэг бүртгэгдсэн санал. Өгөгдөл төслийн хавтас дахь surveys.sqlite3 файлд хадгалагдана.

Corgly аппыг Slack сувагтай холбох

How to Connect Corg.ly to a Slack Channel

Хэзээ хэрэглэх вэ: санал асуулгын үр дүнг өөрийн Slack суваг руу илгээх шаардлагатай үед. Өмнө нь санал асуулга үүсгэсэн байна. Slack workspace-д апп суулгах эрхтэй, туршилтын сувагтай, серверийн терминалд хандах боломжтой байх шаардлагатай.

Холбох дараалал

1. https://api.slack.com/apps хаягт өөрийн эрхээр нэвтэрч Slack app үүсгэнэ. Workspace-аа сонгоно.

2. Аппын тохиргооноос Incoming Webhooks хэсгийг нээж Activate Incoming Webhooks-ийг идэвхжүүлнэ.

3. Add New Webhook to Workspace сонгож туршилтын сувгаа заагаад Authorize дарна. Байгууллагын бодлогоос хамааран админы зөвшөөрөл шаардагдаж болно.

4. Үүссэн webhook URL-ийг хуулна. Хаяг нь нууц тул тайлан, зураг, Git repository-д оруулахгүй.

5. Ажиллаж байгаа Corg.ly серверийг Ctrl+C-ээр зогсооно. Төслийн хавтас дахь терминалд дараах командыг ажиллуулна. “Slack Webhook URL:” гэсэн асуулт гарсны дараа webhook URL-ээ оруулаад Enter дарна. Оруулсан утга дэлгэцэд харагдахгүй.

python3 -c 'import getpass,os,runpy; os.environ["SLACK_WEBHOOK_URL"]=getpass.getpass("Slack Webhook URL: "); runpy.run_path("server.py",run_name="__main__")'

6. Аппыг нээж санал асуулгын карт дээрх “Үр дүнг Slack руу илгээх” товчийг нэг удаа дарна.

Амжилтыг батлах

Интерфейст “Үр дүнг Slack суваг руу илгээлээ.” гэсэн мэдэгдэл гарч, сонгосон Slack сувагт асуулт болон сонголт бүрийн саналын тоо очсоныг шалгана. Мэдэгдэл ирээгүй бол амжилттай гэж тооцохгүй. Холболтгүй үед тохируулгын мэдэгдэл, Slack хүсэлт бүтэлгүйтвэл дахин оролдох заавар гарна.

Холбоотой лавлагаа

POST /api/polls/{poll_id}/slack замыг ашиглана. Бүрэн хүсэлт, хариу, алдааг API Reference хэсгээс харна. Дахин товч дарахад шинэ Slack мессеж илгээгдэнэ. Webhook нь үүсгэхэд сонгосон сувагт холбогддог [5].

Санал өгөх болон үр дүн шалгах

How to санал асуулгад санал өгөх

Хэзээ хэрэглэх вэ: бэлэн санал асуулгын нэг сонголтод саналаа өгөх үед. Сервер ажиллаж, дор хаяж нэг санал асуулга үүссэн байх шаардлагатай.

1. http://127.0.0.1:8000 хаягийг нээгээд асуултын картыг олно. 2. Нийт санал болон сонгох хувилбарын одоогийн тоог тэмдэглэнэ. 3. Хүссэн сонголтын товчийг нэг удаа дарна. 4. “Таны саналыг бүртгэлээ.” гэсэн мэдэгдлийг шалгана.

Баталгаажуулалт: тухайн сонголтын тоо болон нийт санал тус бүр 1-ээр нэмэгдсэн байна. Хуудсыг шинэчлэхэд шинэ дүн хэвээр үлдэнэ. Энэ сургалтын хувилбар давхар санал өгөхийг хориглодоггүй тул товчийг давтан дарахгүй.

Холбоотой Reference: POST /api/polls/{poll_id}/votes, GET /api/polls/{poll_id}.

How to санал асуулгын үр дүнг шалгах

Хэзээ хэрэглэх вэ: санал асуулгын нийт дүнг интерфейс болон API-аар тулгаж шалгах үед. Сервер ажиллаж, санал асуулгын карт дээрх ID мэдэгдэж байх шаардлагатай.

1. Шалгах санал асуулгын ID-г карт дээрээс авна. 2. Сонголт бүрийн санал болон “Нийт санал” утгыг тэмдэглэнэ. 3. Төслийн өөр терминалд дараах командыг ажиллуулна. Жишээ дэх 1-ийг өөрийн ID-аар солино.

curl -s http://127.0.0.1:8000/api/polls/1

4. Хариу дахь options массивын votes утгуудыг нэмээд total_votes утгатай харьцуулна. Асуултын ID ба question нь зөв картыг зааж байгааг мөн шалгана.

Баталгаажуулалт: интерфейсийн нийт санал, API-ийн total_votes, options дахь votes-ийн нийлбэр гурав ижил байна. Хэрэв санал асуулга олдохгүй бол ID-гаа дахин шалгана.

Холбоотой Reference: GET /api/polls, GET /api/polls/{poll_id}.

Нийтийн HTTP API Reference

Суурь хаяг: http://127.0.0.1:8000. Энэ төслийн нийтэд хэрэглэх интерфейс нь доорх 5 HTTP endpoint юм. server.py доторх туслах функц, handler нь хэрэглэгчийн public API-д тооцогдохгүй.

Хүсэлт илгээхийн өмнөх шалгалт

Сервер ажиллаж байгаа, Python 3.10+, 8000 порт боломжтойг шалгана. POST хүсэлт JSON объект байна. Хүсэлтийн body 1–16384 байт; хоосон JSON шаардлагатай үед {} илгээнэ. Slack замд серверийн SLACK_WEBHOOK_URL шаардлагатай. Энэ байрлал нь лабораторийн Chinchilla бүлэг 7, хуудас 92 гэсэн prerequisite шаардлагыг хэрэгжүүлнэ [1, 3].

Санал асуулга үүсгэх хүсэлт

curl -s -X POST http://127.0.0.1:8000/api/polls \
  -H 'Content-Type: application/json' \
  -d '{"question":"Meeting day?","options":["Mon","Tue"]}'

Санал өгөх хүсэлт

curl -s -X POST http://127.0.0.1:8000/api/polls/1/votes \
  -H 'Content-Type: application/json' \
  -d '{"option_id":1}'

Дээрх 1 ID-ууд зөвхөн жишээ. Үүсгэх хүсэлтийн хариу дахь poll id болон options[].id утгыг ашиглана. POST body-г зөв JSON-оор илгээхгүй бол 400 буцна.

WEEK 07 / USER DOCUMENTATION

Интерфейсийн бичвэрийн сайжруулалт

Харьцуулалтын өмнөх текстүүд нь энэ шинэ төслийн анхны санал болгосон хувилбарууд; өмнө ашиглагдаж байсан бүтээгдэхүүний бичвэр биш. Дараах хувилбарууд аппын интерфейс болон серверт хэрэгжсэн. Лабораторийн Chinchilla бүлэг 3, хуудас 27–30 гэсэн гурван дүрмийг хэрэглэв [1, 3].

Алдааны мэдэгдэл

Өмнө: Таны оруулсан асуулт системийн шаардлагад нийцэхгүй байгаа тул дахин зөв мэдээлэл оруулж оролдоно уу.

Дараа: Асуултаа 1–200 тэмдэгтээр бичнэ үү.

Үг: 14 → 5; бууралт 64.3%. Дүрэм: Reducing cognitive load. Алдааны учрыг тэмдэгтийн хязгаартай нь шууд хэлж, засах үйлдлийг заав.

Хоосон төлөв

Өмнө: Одоогийн байдлаар системд ямар нэгэн санал асуулгын мэдээлэл бүртгэгдээгүй байгаа болно.

Дараа: Санал асуулга алга. Эхнийхээ асуулгыг үүсгээрэй.

Үг: 11 → 6; бууралт 45.5%. Дүрэм: Keeping it short. Мэдээлэлгүйг товчилж, дараагийн үйлдлийг нэмэв.

Эхлэх зөвлөмж

Өмнө: Санал асуулга үүсгэх үйлдлийг гүйцэтгэхийн тулд доорх маягтад шаардлагатай асуулт болон сонголтуудын мэдээллийг оруулах хэрэгтэй.

Дараа: Асуултаа бичээд хоёр сонголт нэмээрэй.

Үг: 15 → 5; бууралт 66.7%. Дүрэм: Involving the user. Хэрэглэгчид шууд хандаж, хийх хоёр үйлдлийг нэрлэв.

Хэмжилтийн арга

Үгийн тоог whitespace-ээр салган тоолов. Давтамжийг жижиг үсэгт шилжүүлсэн token бүрээр тоолсон; цэг тэмдгийг token-оос хасаагүй. Бүрэн тооллого microcopy_metrics.json файлд бий. “байгаа” гэсэн token алдааны өмнөх хувилбарт 1, дараахад 0; “Санал” гэсэн token хоосон төлөвт өмнө 1, дараа 1; “мэдээллийг” эхлэх зөвлөмжид өмнө 1, дараа 0 удаа байна.

Уншигдах байдлыг засах үйлдэл тодорхой эсэх, илүү үг багассан эсэх, хэрэглэгчид хандсан эсэх гэсэн шалгуураар редакцын түвшинд үнэлэв. Монгол хэлэнд баталгаажаагүй англи readability томьёогоор оноо гаргаагүй; хэрэглэгч оролцуулсан туршилт хийгдээгүй. Diff нь microcopy.diff файлд хадгалагдсан.

Standup болон retrospective

Standup-д тухайн өдөр бичиж буй Tutorial алхам, шалгаж буй кодын жишээ, засаж буй microcopy-г нэрлэнэ. Энэ нь гүйцэтгэсэн уулзалтын протокол биш, ганцаарчилсан ажлын явцыг хянах загвар юм.

Retrospective-д How-to дотор API хүснэгт оруулахгүй байх, Tutorial-д хэт олон салбар нөхцөл нэмэхгүй байх, микротекстийн уртыг багасгахдаа засах үйлдлийг үлдээх гэсэн шийдвэрийг үнэлнэ. Эдгээрийг дараагийн засварт шалгах асуулт болгон ашиглана.

Долоо хоногийн эргэцүүллийн дүн шинжилгээ

1. Bhatti-ийн 10 алхмын шаардлага нь эхний хэрэглээний хүрээг тодорхой болгоход нөлөөлнө. Tutorial-д Slack тохируулахыг хавсаргавал анхны зорилго сарних учраас тусдаа How-to болгосон. Энэ шийдвэр лабораторийн зааварт тэмдэглэсэн бүлэг 2, хуудас 31–32-той холбогдоно [1, 2].

2. Chinchilla-ийн cognitive load гэсэн шаардлагыг цаашдын интерфейст хэрэглэж болно. “Оролт буруу” гэх ерөнхий мэдэгдлээс илүү “Асуултаа 1–200 тэмдэгтээр бичнэ үү” гэсэн засах үйлдэлтэй текст хэрэгтэй. Энэ хэрэглээг зааврын бүлэг 3, хуудас 27–30 гэсэн заалттай холбов [1, 3].

3. Онол ба хэрэгжилтийн хамгийн том зөрүү нь оролцогчийн таних тэмдэггүй санал өгөх загвар юм. Баримтжуулалт ойлгомжтой байсан ч нэг хүн олон удаа санал өгч чадна. Бодит хэрэглээнд нэвтрэлт, саналын хязгаарлалт, хүртээмжийн болон хэрэглэгчийн туршилт нэмж хийх шаардлагатай.

Эдгээр нь хэрэгжилтэд тулгуурласан техникийн эргэцүүлэл. Оюутны өөрийн суралцах туршлага, зарцуулсан хугацаа, хийгээгүй уулзалтын тухай баримт зохиож оруулаагүй.
